# Atlas – Data Lineage Documentation
**Sprint 4 | Atlas v0.4 Baseline**

Every KPI, insight, and recommendation served by Atlas traces back to a deterministic synthetic source record. This document provides the complete lineage chain for all eight primary datasets.

---

## Lineage Framework

```
data/versions/<vN_seed42_label>/     ← Immutable snapshot (generated Sprint 3)
         │  snapshot_raw_to_version()
         ▼
data/raw/*.parquet                   ← Promoted version; stable ETL read path
         │  extract_all()  [etl/extractors/extract.py]
         ▼
Extract Layer                        ← Schema validation, type casting, metrics
         │  transform_all()  [etl/transformers/transform.py]
         ▼
Transform Layer                      ← Cleaning, FK resolution, enrichment, rejects
         │
data/staging/*.parquet               ← Always written; DB-independent transform output
         │  load_all()  [etl/loaders/load.py]
         ▼
┌─────────────────────────────────────────────────────────────┐
│  PostgreSQL                                                 │
│  raw.*        ← verbatim source (business keys preserved)  │
│  staging.*    ← fully typed, FK-resolved, no FK constraints │
│  warehouse.*  ← star schema: dim_* + fact_* (Sprint 2)     │
│  analytics.*  ← 10 live SQL views (Sprint 2)               │
│  pipeline.*   ← ETL run log, DQ audit trail                │
└─────────────────────────────────────────────────────────────┘
         │  FastAPI /api/v1/...  [Sprint 6]
         ▼
REST API Layer
         │
         ▼
Atlas Intelligence Modules           ← 8 hubs (Sprint 7)
```

## Dataset 1 — Customer Master

| Stage | Artefact | Key Operation |
|---|---|---|
| **Raw** | `data/raw/dim_customer.parquet` | Generated by `customer_generator.py`; 500K rows, seed=42 |
| **Transform** | `data/staging/dim_customer.parquet` | FK resolution (country_code→country_id, channel_code→channel_id); signup_date→signup_date_key; CLV band assignment; churn_risk_score=0.0 |
| **Warehouse** | `warehouse.dim_customer` | TRUNCATE + batch INSERT via `load_dim_customer()` |
| **Analytics View** | `analytics.v_mau_trend` | `COUNT(DISTINCT customer_id)` grouped by `last_activity_date` month |
| **Analytics View** | `analytics.v_customer_value` | CLV band distribution with revenue share |
| **API Endpoint** | `GET /api/v1/executive/kpis` | `{"mau": N, "premium_conversion_rate": 0.20}` |
| **API Endpoint** | `GET /api/v1/customer/segments` | Segment breakdown by lifecycle_stage |
| **Module** | Executive Command Center, Customer Intelligence Hub | |

**Executive KPI trace — Monthly Active Users:**
```
dim_customer.last_activity_date
  → v_mau_trend: COUNT(DISTINCT customer_id)
    WHERE DATE_TRUNC('month', last_activity_date) = current_month
  → /api/v1/executive/kpis → mau field
  → Executive Command Center → MAU KPI card
```

**Executive KPI trace — Activation Rate:**
```
fact_customer_journey.reached_activation (BOOLEAN, TRUE = 1)

  → /api/v1/growth/funnel → activation_rate field
```

## Dataset 3 — Transactions

| Stage | Artefact | Key Operation |
|---|---|---|
| **Raw** | `data/raw/fact_transactions.parquet` | Generated by `transaction_generator.py`; ~7.2M rows at full scale; card, FX, transfer, investment, subscription, crypto |
| **Transform** | `data/staging/fact_transactions.parquet` | product_code→product_id; country_code→country_id; transaction_date→transaction_date_key; transaction_timestamp construction; status enum validation |
| **Warehouse** | `warehouse.fact_transactions` | TRUNCATE + batch INSERT (5,000 rows/batch) |
| **Analytics View** | `analytics.v_cohort_retention` | CTE: signup cohort → activity month → period offset → COUNT(retained) / cohort_size |
| **API Endpoint** | `GET /api/v1/customer/cohort-retention` | Retention matrix (cohort × period 0–24) |
| **API Endpoint** | `GET /api/v1/revenue/trend` | Aggregated from fact_revenue (derived from this table) |
| **Module** | Customer Intelligence Hub, Revenue Intelligence Hub |  |

**Executive KPI trace — Cohort Retention:**
```
fact_transactions.transaction_date, customer_id
  → v_cohort_retention CTE:
      signup_cohort = DATE_TRUNC('month', signup_date)
      activity_month = DATE_TRUNC('month', transaction_date)
      period_number = months between cohort and activity
  → COUNT(DISTINCT customer_id) / cohort_size × 100
  → /api/v1/customer/cohort-retention → retention_matrix
  → Customer Intelligence Hub → Cohort retention heatmap
```

## Dataset 4 — Product Events

| Stage | Artefact | Key Operation |
|---|---|---|
| **Raw** | `data/raw/fact_product_events.parquet` | Generated by `product_event_generator.py`; ~11.5M rows at full scale; adoption events + recurring logins + 4 fraud/risk event types |
| **Transform** | `data/staging/fact_product_events.parquet` | product_code→product_id; country_code→country_id; event_date_key; event_timestamp; JSONB event_properties serialised to string |
| **Warehouse** | `warehouse.fact_product_events` | TRUNCATE + batch INSERT |
| **Analytics View** | `analytics.v_product_adoption` | COUNT(DISTINCT customer_id) per product per month; DAU/MAU stickiness ratio |
| **API Endpoint** | `GET /api/v1/product/adoption` | Per-product adoption rate and MAU |
| **API Endpoint** | `GET /api/v1/product/stickiness` | DAU/MAU ratio per product |
| **API Endpoint** | `GET /api/v1/operations/fraud-summary` | fraud_flagged counts and clearance rate |
| **Module** | Product Intelligence Hub, Operational Intelligence Hub |  |

**Executive KPI trace — Product Stickiness:**
```
fact_product_events.event_date, customer_id, product_id
  → v_product_adoption:
      DAU = COUNT(DISTINCT customer_id) WHERE event_date = yesterday
      MAU = COUNT(DISTINCT customer_id) WHERE event_date IN current month
      stickiness_ratio = DAU / MAU
  → /api/v1/product/stickiness → per-product stickiness
  → Product Intelligence Hub → Stickiness gauge

Fraud lineage:
fact_product_events WHERE event_type = 'fraud_flagged'
  → COUNT(*) / completed_transaction_count × 100 = fraud_flag_rate
  → /api/v1/operations/fraud-summary → fraud_rate field
  → Operational Intelligence Hub → Fraud section
```

## Dataset 5 — Revenue

| Stage | Artefact | Key Operation |
|---|---|---|
| **Raw** | `data/raw/fact_revenue.parquet` | Derived from `fact_transactions` by `pipeline_orchestrator.py` Stage 5; daily grain; all revenue types |
| **Transform** | `data/staging/fact_revenue.parquet` | product_code→product_id; country_code→country_id; revenue_date_key; transaction_type→revenue_type mapping; zero-fee rows excluded (TRANSFER_FREE, savings) |
| **Warehouse** | `warehouse.fact_revenue` | TRUNCATE + batch INSERT |
| **Analytics View** | `analytics.v_monthly_business_summary` | SUM(net_revenue_gbp) by month by revenue_type |
| **Analytics View** | `analytics.v_revenue_by_geography` | Revenue by country and region with ARPU |
| **API Endpoint** | `GET /api/v1/revenue/summary` | Revenue breakdown by type for period |
| **API Endpoint** | `GET /api/v1/executive/kpis` | revenue_mtd, revenue_growth_mom |
| **Module** | Revenue Intelligence Hub, Executive Command Center |  |

**Executive KPI trace — MoM Revenue Growth:**
```
fact_revenue.net_revenue_gbp, revenue_date
  → v_monthly_business_summary:
      SUM(net_revenue_gbp) GROUP BY year, month_number
  → MoM growth = (M - M-1) / M-1 × 100
  → /api/v1/executive/kpis → revenue_growth_mom field
  → Executive Command Center → Revenue Growth KPI card
```

## Executive Command Center — Composite Health Score Lineage

The Business Health Score (0–100) is the single most important KPI in Atlas. Its lineage spans all five analytical domains:

```
┌─────────────────────────────────────────────────────────┐
│  Business Health Score Component Lineage                │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Activation Rate (weight 25%)                          │
│  └─ fact_customer_journey.reached_activation           │
│     └─ v_acquisition_funnel.overall_conversion_pct     │
│                                                         │
│  30-Day Retention (weight 25%)                         │
│  └─ fact_transactions.transaction_date + dim_customer  │
│     └─ v_cohort_retention.retention_rate_pct (p0→p1)  │
│                                                         │
│  Revenue Growth MoM (weight 20%)                       │
│  └─ fact_revenue.net_revenue_gbp                       │
│     └─ v_monthly_business_summary (M vs M-1 delta)     │
│                                                         │
│  NPS Proxy (weight 15%)                                │
│  └─ dim_customer.customer_segment distribution         │
│     └─ % satisfied − % at-risk segments               │
│                                                         │
│  Operational Health (weight 15%)                       │
│  └─ fact_support.status (P1 unresolved rate proxy)     │
│     └─ v_support_performance.resolution_rate_pct       │
│                                                         │
│  → GET /api/v1/executive/health-score                  │
│  → {"score": 78.4, "rating": "Healthy"}               │
│  → Executive Command Center → Health Score card        │
└─────────────────────────────────────────────────────────┘
```
